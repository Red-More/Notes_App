## 0.1 本章要解决什么问题

这一章不教你任何一条命令。它只做两件事：

1. 给你一张**七层栈全景图**，让你知道后面每一章在整条链上的位置。

## 0.3 七层栈逐层定义

| 层 | 名称 | 一句话职责 | 本项目对应物 |
|---|---|---|---|
| 1 | Rust 语言与类型系统 | 保证内存安全、线程安全、错误可处理 | `LocalMnnState`、`Worker`、`!Send` 的 `Llm` |
| 2 | 包管理与构建 | 声明依赖、选择 feature、指定目标平台 | `src-tauri/Cargo.toml`、`Cargo.lock`、`local-mnn` |
| 3 | Rust 调 C++（FFI） | 用 C ABI 跨语言传值和传指针 | `mnn-rs-sys` 的 wrapper 与 `extern "C"` 声明 |
| 4 | 推理引擎内部 | 把模型文件变成 token 输出 | MNN 3.6.1 的 `MNN::Transformer::Llm` |
| 5 | 原生库与链接 | 把 `.a`/`.so` 和符号拼成可执行文件 | `libMNN.a` → `libmnn.a` → `mnn_smoke` |
| 6 | 构建工具链 | 用 CMake/Ninja/NDK 生成目标平台产物 | NDK 28.2.13676358、`arm64-v8a`、`android-24` |
| 7 | 操作系统与硬件 | 装载、执行、调度、限权 | Android 14、ELF64 AArch64、`/data/local/tmp` |

## 0.4 术语索引（按首次出现的大致顺序）

### A. 模型与推理

**LLM（大语言模型）**
定义：用大量文本训练的神经网络，根据已有上下文预测下一个 token。
类比：读过很多书的实习生，你给开头，他往下接。
本项目：Qwen3-0.6B，0.6B 指 6 亿参数。

**参数（parameter）**
定义：神经网络里可学习的数值，通常以矩阵/张量形式存储。
类比：实习生的“记忆突触”，数量决定模型容量，也决定文件大小。

**推理（inference）**
定义：用已训练好的参数做前向计算，得到输出；不更新参数。
类比：考试答题，不再学习。

**token**
定义：模型处理文本的最小单位，可能是一个字、一个词或词的一部分。
类比：乐高积木的最小块；中文里一个 token 可能是一个字，也可能半个词。
本项目：`tokenizer.mtok` 负责文本与 token 的双向转换。

**tokenizer（分词器）**
定义：把字符串切成 token id 序列，并能把 id 解回文本的组件。
类比：翻译官兼速记员，负责“人话”和“模型话”的互译。

**prefill（预填充）**
定义：把整段 prompt 一次性送进模型，建立 KV cache 的阶段。
类比：开会前先把整份资料读一遍。

**decode（解码）**
定义：自回归地一次生成一个 token，直到停止条件满足。
类比：读完资料后，逐字往下写。

**KV cache**
定义：缓存每一层注意力机制的 key/value，避免解码时重算历史 token。
类比：写到第 10 页时，不必把前 9 页重新读一遍。

**量化（quantization）**
定义：用更低比特（如 4-bit）存储权重/激活，换取更小体积和更高带宽利用率。
类比：把高清照片压成 JPEG；看得清，但细节有损。

**4-bit block quantization**
定义：每 N 个参数为一组（block），共享一组缩放因子，参数本身存 4 位。
类比：一盒 32 支铅笔共用一张价签，而不是每支都贴价签。

**采样（sampling）**
定义：从模型输出的概率分布中挑下一个 token 的过程。
类比：不是每次都选“最可能”，而是按温度和候选范围做有随机性的选择。

**temperature / top-k / top-p**
定义：分别控制随机性、候选数量、累计概率阈值。
类比：temperature 是“胆子”，top-k 是“只看前几名”，top-p 是“够票数就停”。

**GGUF**
定义：llama.cpp 的模型文件格式，单文件内含元数据、词表与张量。
类比：一个压缩包，里面什么都有。

**`.mnn`**
定义：MNN 的模型格式；LLM 场景通常是多文件目录，不是单文件。
类比：一套家具，分成板材、螺丝、说明书几个箱子。

### B. 包管理与构建

**crate**
定义：Cargo 管理的最小编译单元，可以是一个库或一个可执行程序。
类比：一块乐高积木；有名字、有接口、有依赖。

**Cargo.toml**
定义：crate 的清单文件，声明包信息、依赖、feature、目标。
类比：餐厅的菜单和采购单。

**Cargo.lock**
定义：锁定依赖精确版本与校验和的文件，保证可重复构建。
类比：采购单的“最终成交记录”，写清楚每家供应商的哪个批次。

**feature**
定义：编译期可开关的能力集合，用来裁剪代码和依赖。
类比：买车时的选装包；不选天窗，车架上就不会有天窗。

**optional dependency（可选依赖）**
定义：默认不引入，只有某个 feature 打开时才参与构建的依赖。
类比：可拆卸的拖车钩。

**`dep:` 语法**
定义：在 feature 定义中显式引用一个可选依赖，避免自动生成同名隐式 feature。
类比：给选装包挂一个明确编号，避免和车名混淆。

**target triple（目标三元组）**
定义：描述编译目标的字符串，如 `aarch64-linux-android`。
类比：快递面单上的“国家-城市-街道”；写错就送不到。

**cross compilation（交叉编译）**
定义：在一种平台上生成另一种平台的可执行文件。
类比：在厨房做好菜，装进保温箱送到另一个城市。

**host / target**
定义：host 是编译发生的平台，target 是产物运行的平台。
类比：厨房与餐桌。

**NDK（Native Development Kit）**
定义：Android 提供的 C/C++ 交叉编译工具链与平台库。
类比：一套“去 Android 国”的专用工具箱，里面有编译器、链接器、系统头文件。

**ABI（Application Binary Interface）**
定义：二进制层面的约定，包括调用约定、参数布局、结构体对齐、符号命名。
类比：插头和插座的形状；电压对了，形状不对也插不上。

**API level**
定义：Android 平台版本的整数编号，如 `android-24`。
类比：目的地的最低道路等级；低于它，某些桥你过不去。

### C. FFI 与链接

**FFI（Foreign Function Interface）**
定义：一种语言调用另一种语言函数的机制。
类比：两个国家的人通过同声传译交流。

**C ABI**
定义：C 语言的二进制调用约定；因为稳定、简单，常被用作跨语言“通用语”。
类比：国际会议用英语，不因为英语最好，而因为大家都认。

**`extern "C"`**
定义：告诉编译器“这个函数按 C 的规则命名和调用”，不要做 C++ 名字修饰。
类比：给函数挂一个国际通用的门牌号。

**name mangling（名字修饰）**
定义：C++ 编译器把命名空间、类、参数类型编码进符号名的机制。
类比：把“张三（研发部/前端组）”压缩成一串内部工号；人能看懂才怪。

**wrapper（封装层）**
定义：包在 C++ API 外面的一层薄 C 函数，负责转换类型、捕获异常、隐藏类。
类比：给一台进口机器加一个标准插座面板。

**opaque handle（不透明句柄）**
定义：只暴露一个指针类型，调用者不知道内部结构，只能把它传回给库函数。
类比：给你一张寄存柜小票；你不知道柜子内部，但凭票取物。

**build.rs**
定义：Cargo 在编译 crate 前运行的小程序，用来编译 C 代码、探测路径、输出链接指令。
类比：开工前的现场勘测员。

**link search path（链接搜索路径）**
定义：链接器查找库文件的目录列表，通常由 `-L` 或 `cargo:rustc-link-search` 提供。
类比：去仓库找零件时，先看哪几个货架。

**`-l<name>`**
定义：让链接器寻找 `lib<name>.a` 或 `lib<name>.so`（Windows 规则不同）。
类比：报零件名，仓库按命名规则去货架取货。

**static library（静态库，`.a`）**
定义：一堆目标文件的归档，链接时按需抽取。
类比：零件箱，装配时挑需要的零件。

**shared library（动态库，`.so`）**
定义：运行时才装载的共享对象，可被多个进程复用。
类比：公共工具间，谁需要谁进去用。

**symbol（符号）**
定义：目标文件里表示函数或变量的名字及其地址信息。
类比：零件上的编号；链接器靠它找“谁引用了谁”。

**linker（链接器）**
定义：把多个目标文件、库、符号引用合并成可执行文件的工具。
类比：总装车间。

**ELF**
定义：Linux/Android 使用的可执行与可链接文件格式。
类比：标准集装箱；里面分区装代码、数据、符号、依赖。

**PIE（Position Independent Executable）**
定义：可加载到任意地址执行的可执行文件，ELF 类型常显示为 `DYN`。
类比：可折叠家具，放哪都能立起来。

**`LD_LIBRARY_PATH`**
定义：动态链接器在启动时额外搜索 `.so` 的目录列表。
类比：告诉快递员“除了默认地址，也去这个临时仓库找”。

### D. Android 与硬件

**APK**
定义：Android 应用安装包，本质是 zip，内含 dex、资源、`.so`。
类比：一个整装行李箱。

**jniLibs**
定义：Gradle 工程中存放按 ABI 分目录的原生库的默认位置。
类比：行李箱里按尺码分格的夹层。

**ABI 目录名**
定义：`arm64-v8a`、`armeabi-v7a`、`x86_64` 等，对应不同指令集。
类比：鞋码；码数不对，穿不上。

**uid**
定义：Android 给每个应用分配的 Linux 用户 ID，用于隔离文件与进程权限。
类比：每家每户的门禁号。

**SELinux**
定义：Android 的强制访问控制机制，在 uid 之外再加一层“域”限制。
类比：小区门禁之外，还有保安按“访客类型”放行。

**`/data/user/0/<pkg>`**
定义：应用私有数据目录；`/data/data` 通常是指向它的兼容路径。
类比：应用自己的家，别的应用进不来。

**`/data/local/tmp`**
定义：shell 用户可读写的临时目录，常用于推送测试二进制。
类比：公共实验台，谁都能放东西，但不是你家。

**NEON**
定义：ARM 的 SIMD（单指令多数据）扩展，一次算多个数。
类比：一排工人同时拧同一排螺丝。

**FP16**
定义：16 位半精度浮点，比 FP32 省一半带宽，精度低一些。
类比：用更小的盒子装同样的货，能多装几件，但易碎品要小心。

**thermal throttling（散热降频）**
定义：设备温度过高时主动降低 CPU 频率，防止过热。
类比：跑步太久会喘，身体自动降速。

## 0.5 三条最重要的“因果链”

术语不是孤立的。你至少要记住三条因果链：

**第一条：feature → 依赖 → 工具链 → 产物**

```text
local-mnn feature
  └─ 启用 mnn-rs（optional dep）
       └─ mnn-rs 启用 cpu/static/llm
            └─ mnn-rs-sys 的 build.rs 找 MNN_LIB_DIR / MNN_INCLUDE_DIR
                 └─ 链接 libmnn.a
                      └─ 产物里出现 MNN 代码
```

所以“默认桌面构建不需要 NDK”，不是巧合，而是 feature 在编译期把整条链剪掉了。

**第二条：wrapper → C ABI → 符号 → 链接**

```text
C++ 类 MNN::Transformer::Llm
  └─ C wrapper 函数 mnn_llm_create（extern "C"）
       └─ 符号名固定，不带 C++ 修饰
            └─ Rust 声明 extern "C" { fn mnn_llm_create(...) }
                 └─ 链接器在 libmnn.a 里找到定义
```

任何一环名字对不上，就是 `undefined reference`。

**第三条：模型格式 → 加载方式 → 内存 → 速度**

```text
多文件 .mnn 目录
  └─ config.json 指定后端/线程/采样
       └─ 权重读入/映射到内存
            └─ prefill 建 KV cache
                 └─ decode 逐 token 生成
                      └─ 受内存带宽与散热限制
```

这解释了为什么“换个更小的量化档位”常常比“多开两个线程”更有效。

## 0.6 常见坑：术语误用导致的错误判断

**坑 1：把 `DYN` 当成“动态库”**
`readelf -h` 显示 `Type: DYN`，有人立刻说“这是动态库”。不对。PIE 可执行文件也是 `DYN`；区别看它有没有 `INTERP` 段、有没有 `main` 入口。判别方法：`readelf -l` 看是否有 `INTERP`，`readelf -d` 看是否有 `NEEDED`。

**坑 2：把“静态链接”理解成“没有动态依赖”**
静态链接 MNN 只意味着 MNN 的代码被装进可执行文件；C++ 标准库、libc、liblog 仍可能是动态依赖。判别方法：`readelf -d mnn_smoke` 看 `NEEDED` 列表。

**坑 3：把 `0x80070005` 当成“需要管理员权限”，或当成“符号链接覆盖冲突”**
这个错误码是 Windows 的“访问被拒”通用信封（`HRESULT_FROM_WIN32(5)`），与 Rust 打印的 `os error 5` 是同一个数字。两种常见解释都被本项目 2026-11-02 的 A–G 实验修正过：真实首因是 NDK 探测顺序扫到了残缺的最大版本；而 `os error 5` 只在 AI 命令沙箱里出现，真实终端 6 次构建未复现（详见第 32 章 `[已验证]`）。判别方法：先看报错是不是 `toolchain file not found`，再确认当前终端是不是受管沙箱，最后才谈权限。

**坑 4：把 tok/s 当成模型能力**
tok/s 受设备、线程、量化、prompt 长度、构建类型影响。没有这些口径的 tok/s 没有比较意义。

## 0.7 小结

- 七层栈的顺序是“应用在上、硬件在下”；构建链是“工具链在下、产物在上”。
- 术语要按“模型/构建/FFI/链接/系统”五组记，不要混在一起背。
- 三条因果链（feature 链、wrapper 链、模型链）是全书的主干。
- 任何数字都要带口径；任何错误都要先判断属于编译、链接、装载还是运行。
- 读不懂某个概念时，先回到这张图问：它属于哪一层？

## 0.8 练习

1. 不看本章，画出七层栈，并在每一层写一个本项目文件名。
   **参考要点**：1 `local_mnn/worker.rs`；2 `Cargo.toml`；3 `mnn-rs-sys` wrapper；4 MNN `llm.hpp`；5 `libMNN.a`；6 NDK/CMake；7 ELF/adb。

2. 解释“静态链接了 MNN，为什么还可能依赖 `libc++_shared.so`”。
   **参考要点**：静态库只包含 MNN 的目标文件；Rust 标准库、wrapper 或其它 C++ 代码仍可能动态依赖 C++ 运行时，需看 `NEEDED`。

3. 给“4-bit 量化让模型变小”补一条因果链，至少经过“block、缩放因子、内存带宽”三个词。
   **参考要点**：4-bit 每参数 4 位 → 每 block 共享缩放因子 → 权重体积下降 → 解码时读权重所需带宽下降 → 在带宽受限的手机上可能更快。
