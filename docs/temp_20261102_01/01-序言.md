# 序：这套东西为什么存在

## 一、先从三个“看起来互不相干”的问题说起

假设你是一个前端开发者，接到一个需求：给笔记应用加一个“本地 AI 助手”，要求在手机上离线回答用户的问题，不上传任何笔记内容。

你会立刻遇到三个问题：

1. **模型从哪里来？** 下载一个 `.gguf` 或 `.mnn` 文件，它到底是“一个文件”，还是“一堆文件的目录”？
2. **谁来算？** JavaScript 跑不动几十亿参数的矩阵乘法；你需要一个 C/C++ 推理引擎，而引擎不能直接听懂 Rust 或 JS。
3. **怎么把它送到手机上？** 你在 Windows 上写代码，手机是 ARM64；编译器、链接器、NDK、ABI、动态库，每一层都可能让程序在启动第一秒就死掉。

这三个问题分别属于“模型与引擎”“跨语言边界”“交叉编译与操作系统”。它们不是三个独立知识点，而是一条链上的三层。任何一层理解错了，最后的症状都一样：**程序能编译，但一运行就报错；或者能运行，但慢到不可用。**

这本书要做的，就是把这条链完整地摊开。

---

## 二、什么是“本地大模型”

**大语言模型（Large Language Model，LLM）**：一种用海量文本训练出来的神经网络，输入一段文字（prompt），输出下一段文字。它的“知识”不是数据库，而是分布在数十亿个参数里的统计规律。

生活化类比：把模型想象成一个读过很多书的实习生。你给他一张便签（prompt），他凭记忆和语感往下写。他不在你的服务器上，也不需要联网——前提是你能把“他”和他的“记忆”一起装进手机。

**本地推理（local inference）**：模型文件放在设备本地，计算也在设备本地完成，输入输出不经过网络。

它带来的不是“更便宜的 API”，而是三种不同的能力：

- **隐私**：笔记、联系人、日程不出设备。对笔记类应用，这是产品前提，不是加分项。
- **离线**：飞机上、地铁里、没有 SIM 卡的平板上都能用。
- **可控**：模型版本、量化档位、系统提示词都由你自己决定，不受厂商 API 变更影响。

代价也很直接：**手机的内存、算力、电量和散热，都远小于一台服务器。** 一个 0.6B（6 亿参数）的模型，用 4-bit 量化后仍要几百 MB；解码速度可能只有每秒十几个 token；持续生成几分钟，机身就会发热降频。

所以“在手机上跑本地大模型”不是一个纯软件问题，它是一个**在资源约束下做工程取舍**的问题。

## 三、为什么是 MNN，而不是只讲 llama.cpp

这个项目有两条线：

- 主线 `Notes_App`：用 `llama-cpp-2` 把 llama.cpp 编进 Rust 静态库，加载 GGUF 模型。已经跑通，真机上有历史基线：Qwen3-0.6B IQ4_XS、3 线程、debug 未优化，解码约 5 tok/s，冷启动首 token 30.8 秒 `[历史记录，见项目调研文档]`。
- 实验分支 `Notes_App-mnn-engine`：在 `experiment/mnn-inference-engine` 上，用 MNN 3.6.1 做对照。基线提交 `8405e3f`，MNN 相关代码目前是工作区改动，尚未提交 `[仓库已核实]`。

为什么要有第二条线？因为 llama.cpp 的基线“能跑但偏慢”，而 MNN 在移动端有另一套调度策略。项目调研文档给出的第三方测量是：Llama 3.2 1B（4-bit）在骁龙 8 Gen 3 上 CPU 解码，MNN 25.7–34.0 tok/s，llama.cpp 3.05–3.29 tok/s `[调研文档引用，非本项目实测]`。

但这本书不会把“MNN 更快”当成结论塞给你。原因有三：

1. 那些数字来自 1B 模型和旗舰机，本项目是 0.6B 和中端机，不能直接外推。
2. MNN 的 LLM 能力主要是 C++ 接口，Rust 侧只有一个社区 crate `mnn-rs`，采用度低、单维护者、构建期还会下载预编译二进制。**集成层的风险，可能大于推理层的收益。**
3. 两个引擎的模型格式不同：GGUF 是单文件，`.mnn` 是多文件目录。模型分发、校验、断点续传都要重做。

所以对照的真正目的，不是“选一个赢家”，而是让你看清：

> 换引擎时，哪些成本是引擎特有的，哪些成本是 Android 工程共有的；哪些结论可以复用，哪些必须重测。

这也是全书反复使用“对照”的原因：每一个 MNN 的概念，都会尽量给出 llama.cpp 的对应物。你学的不是某一个 API，而是**端侧推理的通用结构**。

```text
├─────────────────────────────────────────────────────────────┤
│ 4. 推理引擎内部                                               │
│    模型加载 / 计算图 / prefill / decode / KV cache / 量化       │

│    extern "C" / wrapper / build.rs / 指针所有权                │
├─────────────────────────────────────────────────────────────┤
│ 2. 包管理与构建                                               │
│    crate / feature / optional dep / target triple              │
├─────────────────────────────────────────────────────────────┤

│    所有权 / Result / 闭包 / Send / Sync / cfg                  │
└─────────────────────────────────────────────────────────────┘
```

项目里的真实入口有四个：

- 桌面/移动壳层：`src-tauri/src/lib.rs`，注册 Tauri 命令，初始化 `LocalMnnState`。
- MNN 状态与模型扫描：`src-tauri/src/agent/local_mnn/mod.rs`。
- 独占 worker：`src-tauri/src/agent/local_mnn/worker.rs`。
- 冒烟测试：`src-tauri/examples/mnn_smoke.rs`。

`mnn_smoke` 是最小可运行单元：它不碰数据库、不碰网络、不碰前端，只做“加载模型 → 流式生成 → 打印三段耗时”。把它推到 `/data/local/tmp/mnn` 运行，能把“引擎能不能用”与“Tauri 打包对不对”分开排查。这个拆分方式值得你学走：**先用最小可执行文件验证最底层，再往上叠壳。**

## 五、为什么“能编译”远远不够

初学者最容易把“编译通过”当成终点。在这个项目里，至少有四道独立的门：

1. **编译期**：头文件找得到、C++ 语法对、Rust 类型对。
2. **链接期**：`-lmnn` 找得到 `libmnn.a`，符号名对得上，链接顺序对。
3. **装载期**：`.so` 依赖能在设备上找到，ELF 类型和 ABI 对，页面对齐合规。
4. **运行期**：模型文件路径对、内存够、线程数合理、CPU 指令支持。

任何一道门失败，症状都可能是“程序起不来”。而错误信息往往只给你一个碎片：

- `undefined reference to ...` 是链接期；
- `cannot find -lmnn` 是链接期；
- `library "libc++_shared.so" not found` 是装载期；
- `SIGILL` 是运行期（指令集不匹配）；
- `SIGSEGV` 可能是运行期（空指针、越界、模型损坏）。

这本书的每一章都会尽量把“症状 → 哪道门 → 怎么查”讲清楚。你不需要背命令，但需要建立这张**故障分层地图**。

## 六、怎么读这本书

如果你是第一次接触系统层，建议按完整路线顺序读。前三部分（Rust、构建、FFI）是地基；第四部分（引擎）解释“你在调用的到底是什么”；第五到第七部分（链接、工具链、操作系统）解释“为什么产物是这个样子”。

如果你现在就要复现，走速成路线：先读第 0 章、第 7 章、第 10 章、第 11–14 章，然后照附录 B 做。跑通之后再回头补原理。**允许自己先得到一个能运行的黑盒，再逐步打开它。**

无论哪条路线，请保持三个习惯：

- 每看到一个数字，先问“口径是什么”：设备、模型、量化、线程、构建类型。
- 每看到一个命令，先问“每个参数改变了什么”：是编译期、链接期还是运行期。
- 每看到一个“成功”，先问“证据在哪”：是终端输出、文件属性，还是别人转述。

这不是苛刻，而是这个领域的常态：**同一个 tok/s 数字，换个线程数就能差一倍；同一个“编译成功”，换台机器就可能链接失败。**

## 七、序言小结

- 本地大模型 = 模型文件 + 推理引擎 + 设备算力，三者缺一不可；手机端的关键约束是内存、功耗和散热。
- MNN 与 llama.cpp 的对照，价值在于分离“引擎特性”和“Android 工程共性”，而不是宣布谁更快。
- 这个项目的真实链路是：MNN 源码 → NDK 交叉编译 → `libMNN.a` → Rust FFI → `mnn_smoke` / Tauri 命令 → adb 推送 → 真机运行。
- “编译通过”只是第一道门；链接、装载、运行各有独立的失败模式。
- 所有历史数字都要带口径和证据等级；没有日志的数字，只能当量级参考。

## 序言练习

1. 用一句话解释：为什么“把模型下载到手机”不等于“本地推理已经完成”？
   **参考要点**：还需要能在设备上执行模型的计算引擎、正确的模型格式、足够的内存与算力，以及把引擎送进 App 的构建链路。

2. 列出至少三个“换引擎时不用重做”的模块，以及三个“换引擎时必须重做”的模块。
   **参考要点**：不用重做——Tauri 命令边界、状态机、UI 契约、隐私闸门（如果它们不依赖具体引擎）；必须重做——引擎封装、模型文件形态、分发校验、构建脚本中的引擎编译部分。

3. 为什么本项目要先做 `mnn_smoke`，而不是直接在 Tauri 里加一个“聊天”按钮？
   **参考要点**：最小可执行文件能隔离变量；先验证引擎、链接、ABI、模型路径，再验证 Tauri 打包与前端，否则报错无法定位层级。
