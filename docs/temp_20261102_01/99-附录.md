## 附录 A 命令速查

### A.1 环境与版本确认

| 目的 | 命令 | 参数说明 |
|---|---|---|
| 看 NDK 目录 | `Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\ndk"` | 逐个确认是否含 `build\cmake\android.toolchain.cmake` |
| 看 NDK 版本 | `Get-Content "$NDK\source.properties"` | `Pkg.Revision=28.2.13676358` |
| 看 CMake | `cmake --version` | 第一行是版本；4.x 会触发第 31 章的政策问题 |
| 看 Ninja | `ninja --version` | `mnn-rs-sys` 在 Android 构建时会检查它是否存在 |
| 看 Rust 目标 | `rustup target list --installed` | 应含 `aarch64-linux-android` |
| 看 adb | `adb version` | 确认 platform-tools 在 PATH |
| 看设备 | `adb devices -l` | `-l` 显示型号与传输方式 |

### A.2 MNN 构建（CMake + Ninja）

| 目的 | 命令 | 参数说明 |
|---|---|---|
| 配置 | `cmake -S <src> -B <build> -G Ninja -DCMAKE_TOOLCHAIN_FILE=<ndk>\build\cmake\android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-24 -DANDROID_STL=c++_static -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=<stage> -DMNN_BUILD_SHARED_LIBS=OFF -DMNN_SEP_BUILD=OFF -DMNN_BUILD_LLM=ON -DMNN_LLM_BUILD_DEMO=OFF -DLLM_SUPPORT_HTTP_RESOURCE=OFF -DMNN_KLEIDIAI=OFF` | `-S` 源码、`-B` 构建目录、`-G` 生成器、`-D` 缓存变量 |
| 构建 | `cmake --build <build> --config Release -- -j 4` | `--` 之后的参数传给 Ninja；`-j` 并行度 |
| 只构建某目标 | `ninja -C <build> llm` | 用于快速验证补丁是否生效 |
| 安装 | `cmake --install <build> --config Release` | 产物落到 `CMAKE_INSTALL_PREFIX` |
| 看目标数 | `ninja -C <build> -t targets all \| Measure-Object -Line` | `-t targets` 列出全部目标 |
| 解释重编原因 | `ninja -C <build> -d explain <target>` | 排查“为什么又编了” |
| 只打印不执行 | `ninja -C <build> -n` | dry run |
| 计时 | `Measure-Command { cmake --build <build> -- -j 4 } \| Select-Object TotalSeconds` | 复核“20 分 21 秒” |

### A.3 staging（预编译路线）

```powershell
$stage = "$env:USERPROFILE\mnn-stage\arm64-v8a"
New-Item -ItemType Directory -Force "$stage\lib","$stage\include" | Out-Null
Copy-Item "<build>\libMNN.a" "$stage\lib\libmnn.a"        # 改名以匹配 -lmnn
Copy-Item "<mnn-src>\include\*" "$stage\include\" -Recurse
Copy-Item "<mnn-src>\transformers\llm\engine\include\llm" "$stage\include\llm" -Recurse
```

| 参数 | 说明 |
|---|---|
| `-ItemType Directory -Force` | 目录不存在则建，存在不报错 |
| `Copy-Item src dst` | 复制；`-Recurse` 用于目录 |
| `libMNN.a → libmnn.a` | 唯一目的就是让 `-lmnn` 能找到（第 24 章） |
| `include\llm` | LLM 头文件，install 规则常漏（第 26 章） |

### A.7 常用组合（复制即用）

```powershell

$TOOLS = "$NDK\toolchains\llvm\prebuilt\windows-x86_64\bin"

$env:ANDROID_NDK_HOME = $NDK
$env:NDK_HOME         = $NDK
$env:MNN_LIB_DIR      = "$stage\lib"

cargo build --target aarch64-linux-android --release --features local-mnn --example mnn_smoke

adb push .\mnn_smoke /data/local/tmp/mnn/

```

## 附录 B 从零复现手册

> **前置条件**：Windows 10/11、Node/pnpm（仅 Tauri 侧需要）、Rust（含 `aarch64-linux-android` target）、Android SDK + NDK、CMake、Ninja、Git、adb。
>
> **本书不修改参考仓库**。所有构建产物写在仓库之外（例如 `%USERPROFILE%\mnn-build`、`%USERPROFILE%\mnn-stage`），模型放在你自选的目录。

### 步骤总览

```
01 环境检查 → 02 取源码 → 03 打补丁 → 04 配置 → 05 构建 → 06 安装/staging
   → 07 设环境变量 → 08 编 mnn_smoke → 09 静态检查 → 10 推送 → 11 运行 → 12 记录
```

### 步骤 01：环境检查

```powershell
cmake --version
ninja --version
rustup target list --installed
adb version
Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\ndk"
```

**检查点**

- CMake 能运行（版本记下来，第 31 章的政策问题与它有关）；
- Ninja 存在（Android 构建硬依赖）；
- 列表里有 `aarch64-linux-android`；
- NDK 目录里至少有一个含 `build\cmake\android.toolchain.cmake` 的版本。

**失败信号**

| 现象 | 处理 |
|---|---|
| `cmake` 不是内部或外部命令 | 把 Visual Studio 的 CMake 目录加进 PATH，或从 VS 安装目录找到 `...\CMake\CMake\bin` |
| `ninja` 缺失 | `choco install ninja` 或从 VS 的 Ninja 目录复制 |
| target 缺失 | `rustup target add aarch64-linux-android` |
| NDK 目录里全是“半装”版本 | 只选含 `build/cmake/android.toolchain.cmake` 的，并让 `ANDROID_NDK` 指向它 |

### 步骤 02：获取 MNN 3.6.1 源码

```powershell
git clone --depth 1 --branch 3.6.1 https://github.com/alibaba/MNN.git "$env:USERPROFILE\mnn-src"
```

**检查点**：`$env:USERPROFILE\mnn-src\CMakeLists.txt` 存在；`git -C "$env:USERPROFILE\mnn-src" describe --tags` 显示 `3.6.1`。

**失败信号**：tag 不存在 → 用 `git ls-remote --tags` 找到正确的 tag 名（可能是 `v3.6.1`）。

### 步骤 03：打补丁（LLM CMakeLists）

**目的**：让 `llm` OBJECT library 不再挂 `POST_BUILD`（第 28 章）。

**检查**：

```powershell
Select-String -Path "$env:USERPROFILE\mnn-src\transformers\llm\engine\CMakeLists.txt" -Pattern "POST_BUILD" -Context 4,2
```

**修补**：在 `add_custom_command(TARGET llm POST_BUILD ...)` 外面加 `IF(NOT MNN_SEP_BUILD)`，并在该分支里改用 `file(COPY ...)`。完整替换文本见第 28.3.3 节。

**检查点**：文件里出现 `file(COPY ${CMAKE_CURRENT_LIST_DIR}/include/ DESTINATION`。

**失败信号**：configure 时报 `Target "llm" is an OBJECT library that may not have PRE_BUILD, PRE_LINK, or POST_BUILD commands.` → 补丁位置不对，或 `MNN_SEP_BUILD` 分支条件写反。

> 备选：如果你用 `mnn-rs-sys` 的 `build-from-source` feature，这个补丁由 `build.rs` 自动打（第 28.3.3 节），此步骤可以跳过。

### 步骤 04：配置

```powershell
$NDK = "$env:LOCALAPPDATA\Android\Sdk\ndk\28.2.13676358"
cmake -S "$env:USERPROFILE\mnn-src" -B "$env:USERPROFILE\mnn-build" -G Ninja `
  -DCMAKE_TOOLCHAIN_FILE="$NDK\build\cmake\android.toolchain.cmake" `
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-24 -DANDROID_STL=c++_static `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_INSTALL_PREFIX="$env:USERPROFILE\mnn-stage\arm64-v8a" `
  -DMNN_BUILD_SHARED_LIBS=OFF -DMNN_SEP_BUILD=OFF -DMNN_BUILD_LLM=ON `
  -DMNN_LLM_BUILD_DEMO=OFF -DLLM_SUPPORT_HTTP_RESOURCE=OFF -DMNN_KLEIDIAI=OFF
```

**检查点**

- 输出结尾是 `Generating done`（Ninja 生成器）；
- `$env:USERPROFILE\mnn-build\build.ninja` 存在；
- `CMakeCache.txt` 里 `CMAKE_BUILD_TYPE:STRING=Release`。

**失败信号**

| 报错 | 原因 |
|---|---|
| `Compatibility with CMake < 3.5 has been removed` | CMake 4.x + 旧声明（第 31 章） |
| `Could not find toolchain file` | NDK 不完整或路径错 |
| `Target "llm" is an OBJECT library...` | 补丁没打上 |
| `Ninja` 相关报错 | 生成器不可用或 PATH 问题 |

### 步骤 05：构建

```powershell
Measure-Command {
  cmake --build "$env:USERPROFILE\mnn-build" --config Release -- -j 4
} | Select-Object TotalSeconds
```

**检查点**

- 无 `FAILED:` 行；
- `$env:USERPROFILE\mnn-build\libMNN.a` 存在，体积在 200 MB 量级 `[历史记录：212.07 MB]`；
- 若你记录 target 数：`ninja -C "$env:USERPROFILE\mnn-build" -t targets all | Measure-Object -Line`（历史记录为 459）。

**失败信号**

| 现象 | 处理 |
|---|---|
| `FAILED:` 且无编译器错误文本 | 内存不足，降 `-j` |
| 报某个 `MNN::...` 源文件错误 | 源码版本/补丁不匹配 |
| 构建极慢 | 确认 `CMAKE_BUILD_TYPE=Release`、`-j` 合理 |

### 步骤 06：安装与 staging

```powershell
cmake --install "$env:USERPROFILE\mnn-build" --config Release

$stage = "$env:USERPROFILE\mnn-stage\arm64-v8a"
# 1) 若 install/lib 里是 libMNN.a，复制为 libmnn.a
if (Test-Path "$stage\lib\libMNN.a") {
  Copy-Item "$stage\lib\libMNN.a" "$stage\lib\libmnn.a" -Force
}
# 2) 确保 include 里有 llm/llm.hpp
Test-Path "$stage\include\llm\llm.hpp"
```

**检查点**

- `$stage\lib\libmnn.a` 存在，大小与构建产物一致；
- `$stage\include\MNN\` 下有头文件；
- `$stage\include\llm\llm.hpp` 存在。

**失败信号**

| 现象 | 处理 |
|---|---|
| 只有 `libMNN.a` 没有 `libmnn.a` | 手工复制改名（第 24 章） |
| 没有 `include\llm` | 从源码树 `transformers\llm\engine\include\llm` 复制（第 26 章） |
| include 是空的 | `cmake --install` 失败但没报错，检查 `CMAKE_INSTALL_PREFIX` |

### 步骤 07：设置 Rust 侧环境变量

```powershell
$NDK   = "$env:LOCALAPPDATA\Android\Sdk\ndk\28.2.13676358"
```

### 步骤 12：记录与复核

```powershell
adb logcat -c
1..3 | ForEach-Object {
  "== run $_"
  adb shell "cd /data/local/tmp/mnn && LD_LIBRARY_PATH=. ./mnn_smoke ./Qwen3-0.6B-MNN '用一句话介绍你自己。' 128 4" |
```

**失败信号**：三次数值差异巨大 → 先记录温度，再判断是否降频（第 39 章）。

## 附录 C 常见错误对照表

### C.1 构建期（CMake / Ninja）

| 错误信息 | 原因 | 排查路径 |
|---|---|---|
| `Target "llm" is an OBJECT library that may not have PRE_BUILD, PRE_LINK, or POST_BUILD commands.` | `MNN_SEP_BUILD=OFF` 时 `llm` 是 OBJECT library，却挂了 `POST_BUILD` | 打补丁（第 28.3.3）；或用 `build-from-source` 让脚本自动打 |
| `Compatibility with CMake < 3.5 has been removed from CMake.` | CMake 4.x + 旧 `cmake_minimum_required` | 升声明 / `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` / 降 CMake（第 31 章） |
| `Could not find toolchain file: .../android.toolchain.cmake` | NDK 不完整 | 检查 NDK 目录结构；用只接受完整 NDK 的选择逻辑（第 30 章） |
| `ninja: error: loading 'build.ninja'` | 未 configure 或 `-C` 错 | 先 `cmake -S ... -B ... -G Ninja` |
| `FAILED: ... clang++.exe` 无错误文本 | OOM | 降 `-j`（第 29 章） |
| `install` 后无 `include/llm` | install 规则漏 LLM 头 | 手工复制 `transformers/llm/engine/include/llm` |
| `CMake Error: ... variable is used but not defined` | 缺 `-D` 参数或子工程假设 | 对照第 28.3.1 的参数表 |
| `No rule to make target 'install'` | 生成器/目标名不同 | 用 `cmake --install` 而不是 `ninja install` |

### C.2 链接期（Rust / 链接器）

| 错误信息 | 原因 | 排查路径 |
|---|---|---|
| `cannot find -lmnn` | 搜索目录里没有 `libmnn.a`/`libmnn.so` | 检查 staging 文件名；`cargo build -v` 看 link-search（第 24 章） |
| `undefined reference to 'MNN::Transformer::Llm::create(...)'` | 符号未解析：未链库、顺序问题、或库内是未定义引用 | `llvm-nm -C libmnn.a`；检查 `-l static=mnn` 是否生效 |
| `undefined reference to 'std::__ndk1::...'` | STL 未链接或 ABI 命名空间不一致 | 检查 `c++_static`；`llvm-nm -C` 查库侧命名空间（第 26 章） |
| `file format not recognized` | 架构/格式不匹配 | `llvm-readelf -h` 看 `Machine`；`file` 看格式 |
| `incompatible target` | ABI mismatch | 对比两边的 `Class`/`Machine`/`Flags` |
| `cannot enable both 'static' and 'dynamic'` | 同时启用互斥 feature | 只留一个（`build.rs` 显式 panic） |
| `Ninja build system is required for Android builds` | 缺 Ninja | 安装 Ninja，或把它放进 PATH |
| `ANDROID_NDK_HOME or NDK_HOME must be set for Android builds` | 环境变量缺失 | 设置并确认子进程继承；第 32 章 E 组显示只设 `ANDROID_NDK` 也能成功，若报错来自别的工具则按它要求的名字设 |
| `MNN headers not found!` | `MNN_INCLUDE_DIR` 未设或为空 | 同时设置 `MNN_LIB_DIR` 与 `MNN_INCLUDE_DIR` |

### C.3 运行期（Android 加载 / 权限）

| 错误信息 | 原因 | 排查路径 |
|---|---|---|
| `cannot execute: required file not found` | `PT_INTERP` 或依赖缺失 | `llvm-readelf -l/-d`（第 33、34 章） |
| `Permission denied`（执行时） | 无执行位 / SELinux / noexec | `ls -l`、`ls -Z`、`logcat` 找 `avc: denied`（第 36 章） |
| `CANNOT LINK EXECUTABLE ... library "libX.so" not found` | 依赖未随包/未推送 | `-d` 看 NEEDED；检查 `/data/local/tmp` 或 APK 的 `lib/<abi>/` |
| `dlopen failed: ... is 32-bit instead of 64-bit` | 混了 32 位库 | 清理旧的 `armeabi-v7a` 目录 |
| `cannot locate symbol "__android_log_print"` | 未链 `liblog` 或 API 不一致 | 检查 `-llog` 与 API level |
| `avc: denied { execute }` | SELinux 域不允许执行该标签 | 换到 `/data/local/tmp`；或让 `.so` 随 APK 打包（第 36 章） |
| `java.lang.UnsatisfiedLinkError` | APK 内 `.so` 缺失/ABI 不符 | 解包 APK 看 `lib/arm64-v8a/` |
| 安装报 ABI 不匹配 | APK 无目标 ABI | 先查是否传了 `--target aarch64`；再查 universal flavor；最后才查 `abiFilters`（第 32 章 D 组） |

### C.4 Windows 构建脚本

| 现象 | 原因 | 处理 |
|---|---|---|
| `Android NDK toolchain file not found: ...\ndk\30.0.16248370` | 未设 `ANDROID_NDK`，探测链扫到残缺的最大版本 NDK | `setx ANDROID_NDK <完整 NDK>` → 新开终端重跑；判据 `Test-Path "$env:ANDROID_NDK\build\cmake\android.toolchain.cmake"`（第 32 章 A 组 `[已验证]`） |
| `os error 5` / `0x80070005` / `-2147024891` **只在受管终端**出现 | 命令沙箱写限制（机制细节 `[未复核]`：重写链接目标、把工作区外 NDK 文件标 restricted） | 换真实终端复跑；**不要**加管理员、不要改工程（第 32 章：真实终端 6 次构建未复现 `[已验证]`） |
| 同一命令真实终端成功、沙箱必失败 | 同上（环境假阳性） | 把“执行环境”当成一个变量记录；日志留在 `%TEMP%\notes-android-control\` |
| `os error 183` | 目录“先删后建”，删失败后创建时目标仍在 | 本次未复现 `[未复核]`；仍按目录已存在处理：删除或改名后重试（`clearFolder()` 逻辑，第 32 章） |
| `mergeJniFolders` 重复文件 | 同一个 `.so` 出现在多个 native 源目录 | 只保留一个来源；确认只传一个 `--target`（`abiFilters` 不是必需项） |
| `abiFilters` 注入下次构建消失 | `gen/android` 被 Tauri 重新生成 | 不要依赖注入；用 `--target aarch64`（第 32 章 D 组 `[已验证]`） |
| APK 里缺少 `libc++_shared.so` | NDK 不完整，动态 STL 未正确链接 | 检查 `ANDROID_NDK`；把 NDK 的副本复制进 target **无效**（cargo-mobile2 只从 sysroot 建链） |
| 安装后跑的是旧库 | Gradle 复用旧 APK | 先删 APK 重打（第 32 章 G 组）；或 `assembleArm64Debug -x rustBuildArm64Debug` 强制重打包（仓库文档有记录） |
| `cmake` 找不到 | VS 的 CMake 不在 PATH | 手动把 `...\CMake\CMake\bin` 与 `...\CMake\Ninja` 加进 PATH |
| `LIBCLANG_PATH` 相关报错 | bindgen 需要 libclang | 设置 `LIBCLANG_PATH`；本项目 MNN 路线不需要 bindgen（第 15 章） |

### D.1 三个组件的许可证

| 组件 | 许可证 | 依据 |
|---|---|---|
| MNN（引擎本体） | Apache License 2.0 | MNN 仓库根目录 `LICENSE` `[通用原理]` |

**双许可怎么理解**：许可方同时给出两份许可，**你可以选其中一份**来遵守，不必同时满足两份。选 Apache-2.0 或 MIT 都行，但选定后要按那份的义务执行。

### D.2 Apache-2.0 的主要义务（与本书场景相关）

| 义务 | 具体做法 |
|---|---|
| 保留版权、许可、NOTICE | 随产品附带 `LICENSE` 与 `NOTICE`（例如“关于/开源许可”页面） |
| 标注修改 | 你给 MNN 打的补丁（第 28 章）属于修改，需说明“已修改” |
| 专利授权与终止 | Apache-2.0 含专利授权条款；若你起诉对方专利侵权，授权可能终止 |
| 无担保 | 许可证明确“按原样提供”，不承担质量责任 |
| 不强制开源你的代码 | Apache-2.0 不是 copyleft；你的应用代码可以闭源 |

**静态链接是否允许**：Apache-2.0 允许静态链接，义务仍是保留声明与 NOTICE。这一点与 LGPL 不同（LGPL 对静态链接有“可重新链接”的要求）。

### D.3 MIT 的主要义务

| 义务 | 具体做法 |
|---|---|
| 保留版权与许可声明 | 在分发物中附上 MIT 全文与版权行 |
| 无担保 | 同上 |

MIT 比 Apache-2.0 更短，没有显式专利条款。若你在意专利授权，选 Apache-2.0；若只想最简，选 MIT。

### D.4 修改 MNN 源码的合规动作

第 28 章的补丁改变了 `transformers/llm/engine/CMakeLists.txt`。建议：

1. 把补丁保存为独立文件（`.patch`），并在仓库文档里注明“基于 MNN 3.6.1”；
2. 在 NOTICE 或第三方声明里写“本产品包含修改过的 MNN 3.6.1”；
3. 不要把补丁散落在构建脚本里而不留记录（可复现性也要求这一点）。

### D.5 模型的许可证

**模型不是代码，许可证要单独看**。

- Qwen3-0.6B 的许可证以模型卡/权重目录里的 `LICENSE` 为准；公开资料通常标注为 Apache-2.0，但**引用前必须自己核对**（`[未核实]`）。

### E.3 产物存放原则

**不要只把产物留在 `%TEMP%`**。原因：

- `%TEMP%` 会被系统清理（磁盘清理、重启、策略）；
- 清理工具不会区分“你的 212 MB 静态库”和“临时垃圾”；
- 一旦丢失，重建成本是 20 分钟量级 + 补丁重打 + staging 重拼。

**推荐布局**：

```
%USERPROFILE%\
├─ mnn-src\                     ← 源码（可重克隆，但保留 patch 记录）
├─ mnn-build\                   ← 构建目录（可删，重建慢）
├─ mnn-stage\arm64-v8a\         ← staging（长期保留：lib + include）
│  ├─ lib\libmnn.a
│  └─ include\...
└─ mnn-artifacts\               ← 归档
   ├─ 2026-11-02\
   │  ├─ libmnn.a.sha256
   │  ├─ mnn_smoke.sha256
   │  ├─ mnn_smoke
   │  ├─ build.log
   │  ├─ configure.log
   │  ├─ staging-manifest.txt    ← include 文件清单
   │  └─ run-1.log ~ run-3.log
   └─ ...
```

**归档时至少记录**：

```powershell
Get-FileHash .\libmnn.a -Algorithm SHA256 | Format-List
Get-FileHash .\mnn_smoke -Algorithm SHA256 | Format-List
(Get-ChildItem "$stage\include" -Recurse -File).FullName |
  Set-Content .\staging-manifest.txt
```

**为什么记录 staging 清单**：`libmnn.a` 的哈希能证明“库没变”，但 include 是一堆文件，漏一个头文件就会让下一个人构建失败；清单是最便宜的防呆措施。

### E.4 模型文件的完整性

模型是“多文件目录”，不是单文件。至少要记录：

```powershell
Get-ChildItem .\Qwen3-0.6B-MNN -Recurse -File |
  ForEach-Object { "$($_.Name) $((Get-FileHash $_.FullName -Algorithm SHA256).Hash)" } |
  Set-Content .\model-sha256.txt
```

推送前用同一份清单核对设备上的文件大小（`adb shell "du -sh ..."` 与 `ls -l`）。**只比目录总大小不够**：目录可能“看起来一样大”但缺一个分片。

### E.5 什么算“可复现”

一个可复现的构建记录，至少包含：

1. **工具版本**：CMake、Ninja、NDK、Rust、cargo、adb；
2. **源码版本**：MNN tag + commit、`Notes_App-mnn-engine` 的 commit + 分支；
3. **补丁**：完整 `.patch` 文件；
4. **命令**：实际执行的命令（不是“大概这样”）；
5. **产物哈希**：`libmnn.a`、`mnn_smoke`、模型分片；
6. **环境**：Windows 版本、磁盘剩余空间、内存（影响 `-j` 选择）；
7. **运行环境**：机型、Android 版本、电量、温度；
8. **原始日志**：`configure.log`、`build.log`、`run-*.log`。

缺任何一项，别人只能“照着做一遍看能不能成”，而不是“验证你的结论”。
